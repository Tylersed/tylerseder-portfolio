01 / Internal platform

My Peachtree Portal

A centralized advisor experience that turns scattered links, documents, notices, directory information, and support paths into one organized internal platform.

Year
2026
Role
Product direction + development
Focus
Information architecture
Status
Live internal platform

01 / Context

The problem was not one missing link. It was fragmentation.

Advisors depended on a growing collection of systems, shared documents, bookmarks, email messages, and support requests. The information existed, but finding the right path required memory, context, and repeated help. The portal became a practical layer between people and those systems.

01

Clarity before features

The first responsibility was creating a clear structure for the resources advisors already needed.

02

Mobile by default

Advisors often work away from a desk, so the interface had to remain usable on phones and tablets.

03

Maintainable content

Notices, office details, links, and resources needed an editing workflow that could evolve without rebuilding the site.

02 / System

One organized place to begin.

The portal combines active notices, office information, support navigation, advisor tools, directory access, and resource collections within one visual system.

03 / Process

From complexity to a repeatable operating model.

The process combines discovery, design, implementation, verification, and documentation rather than treating launch as the finish line.

01

Inventory the work

Mapped the tools, documents, office information, and support paths people repeatedly needed.

02

Design the structure

Grouped resources by task instead of by internal ownership, then created a consistent navigation model.

03

Build for real devices

Developed and refined the interface around desktop, tablet, and mobile use rather than treating mobile as an afterthought.

04

Create an operating model

Added editable notices, resource organization, deployment workflows, and documentation so the platform could remain useful after launch.

04 / Outcomes

Useful results without invented metrics.

These outcomes describe capabilities and operating improvements that can be demonstrated without publishing private data or unsupported claims.

Centralized access

Frequently used resources and support paths are available from one responsive starting point.

Consistent experience

The visual system makes unrelated tools feel like part of one company experience.

Operational control

Content can be updated without rebuilding the entire interface.

Foundation for growth

The portal provides a base for future directories, support tools, and internal workflows.
